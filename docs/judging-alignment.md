# Judging Alignment

## Competition Read

Find Evil rewards autonomous incident-response quality, not the number of
parsers exposed. The current product direction is a custom MCP server plus
plan-driven workflow that enforces evidence boundaries and preserves traces.

## Criteria Matrix

| Judging Criterion | Current Product Evidence | Gap To Close Next |
| --- | --- | --- |
| Autonomous execution quality | `run-case` discovers or validates a plan, sequences lanes, records caveats, retries benchmark failures within a cap, preserves failed planned artifacts with a recorded lane adjustment, continues case lanes where summaries remain available, degrades away from questionable disk depth when metadata reports corruption, skips discovered memory placeholder searches with a recorded lane adjustment, and runs a capped claim-promotion review loop with iteration trace. | Deepen lane-specific recovery decisions where a failure can be corrected with a safer alternate artifact or parameter set. |
| IR accuracy | Lane reports keep heuristic pivots separate from claim status; scenario benchmarks validate known fixtures; the claim ledger labels candidate, corroborated, supported, and volatile pivots; optional claim-accuracy manifests score promoted, missed, rejected, and unsafe claim classes. | Extend the current claim-type score into deeper incident-level expected findings. |
| Breadth and depth | Current lanes cover PCAP, mount-free E01 inventory, Autoruns, protected registry hives and decoded payloads, exported UserAssist execution context, memory string pivots, case discovery, multi-artifact lanes, correlation, dossier, and executive output. | Deepen timeline or memory support when the available evidence and guest tools allow it. |
| Constraint implementation | Custom typed CLI/MCP paths, allowlisted guest analyzers, `/cases` path checks, before/after hashes, mount-free disk path, plan validation, and negative path/output/claim-promotion/guest-spoliation tests. | Extend guest constraint coverage as new artifact lanes are added. |
| Audit trail quality | Lane summaries record hashes, commands, raw-output bundles, execution logs, correlation JSON, a claim ledger with source summary paths, and a quality-review iteration trace. | Extend claim support to exact raw-output references and broader correction decision traces. |
| Usability and documentation | README, product docs, case-plan docs, discovery, sample fixtures, dataset notes, architecture, accuracy report, Devpost package draft, demo runbook, execution report, claim ledger, and executive report. | Publish the final repository, record the demo, and attach the agent/tool-call export. |

## Submission Components

The product must still ship all required submission components:

1. Public code repository and open-source license.
2. Live terminal demo video with a self-correction sequence.
3. Architecture diagram with explicit security boundaries.
4. Written project story.
5. Dataset documentation.
6. Accuracy report with evidence-integrity and hallucination/failure notes.
7. Try-it-out instructions.
8. Structured agent/tool execution logs.

## Priority Order

1. Record and publish the submission package.
2. Deepen lane-specific recovery where a safer alternate artifact or parameter
   set can replace a failed path.
